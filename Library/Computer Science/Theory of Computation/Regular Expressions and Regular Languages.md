# Regular Expressions and Regular Languages

> **Summary:** Regular expressions, NFAs and DFAs describe the same class of languages (the regular languages), which is closed under union, concatenation, Kleene star, complement and intersection. Python's `re.fullmatch` is the call that tests whole-string membership.

## What it is

- Theorem 3.3 (regex to NFA) and Theorem 3.4 (DFA/NFA to regex) of Critchlow and Eck show the three formalisms are equivalent. The page does not call this "Kleene's theorem" (that name is not used here as sourced).
- Theorem 3.5 (closure): union, concatenation, complement, Kleene star and intersection of regular languages are regular. Complement by swapping accepting states works for DFAs, not NFAs. For intersection, the page (3.6) describes a pairing construction: the states of the new machine are pairs of states of M1 and M2 (Q1 x Q2), and a pair accepts only when both components accept. The page does not use the name "product construction"; that is the standard term (own gloss).
- Nonregular languages exist: see [[Pumping Lemma for Regular Languages]].

## How it works

Regex to NFA by structural induction on the expression (own inference: the same pattern as [[Induction and Recursion]] / [[Mathematical Induction]], applied to a recursively defined set of expressions; the book names the technique, not these notes). NFA to regex via the R(i,j,k) construction.

Python practice (Python 3.15 docs): `re.fullmatch(pattern, string)` returns a Match only if the whole string matches, so it tests membership of the string in the pattern's language; `re.search` looks anywhere, `re.match` only at the start.

```python
import re
print(bool(re.fullmatch(r"(ab)*", "abab")))   # True
print(bool(re.fullmatch(r"(ab)*", "ababa")))  # False
print(bool(re.match(r"(ab)*", "ababa")))      # True (prefix match only)
```
(The `match` line is consistent with the docs' description of start-only matching; run as own illustration.)

## Key terms

> **Regular language**: a language generated by a regular expression, equivalently accepted by a DFA or NFA (Critchlow and Eck 3.6).

> **Product construction**: standard name (own gloss, not on the Critchlow and Eck page) for the pairing construction that builds an automaton for the intersection of two regular languages: states are pairs (Q1 x Q2) of the two machines' states, accepting only when both accept (construction as described on 3.6).

## Example

Complement: for a DFA accepting L, swap accepting and non-accepting states to accept the complement.

## Contradictions and uncertainties

- Own inference (the fetch tool's, not a sentence on the Python page): Python backreferences such as `(.+) \1` go beyond formal regular expressions. The Python docs only say they exist; no read theory source proves the claim. `unverified`.
- Python docs describe 3.15 (`match` soft-deprecated, `prefixmatch` added); older versions differ. Hence `review-by` 2027-05-23.
- The regex/NFA/DFA equivalence rests on one textbook (theorems read), so `debated` per rule.
